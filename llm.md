# BBC Pipeline Manager — Project Knowledge Base

## Overview

A dual-interface (TUI **+** Webapp) tool for managing Bitbucket Pipelines. Users can list pipelines, view details/steps/variables, read step logs, trigger new pipeline runs, and stop in-progress pipelines. All communication goes through a local Go backend that proxies the Bitbucket Cloud REST API (v2.0).

## Key Architecture Concepts

### Auth Flow

- Each "project" in config has `username` + `app_password` (Bitbucket App Password)
- These are combined as `Basic base64(user:pass)` in HTTP Authorization header
- The Go backend reads config and creates a `BitbucketClient` per project
- The webapp sends a `project_id` (index into the projects array) with each request
- The backend looks up the project's credentials and proxies to Bitbucket

### Two Entry Points

```
bbc-pipeline-tui          # TUI mode (default)
bbc-pipeline-tui -serve   # Start HTTP server on :8080 + serve webapp
bbc-pipeline-tui -port 9090  # Custom port
```

### API Endpoints (Go Backend → Webapp)

All are `GET` unless noted. Base: `http://localhost:8080/api`

| Method | Path | Params | Returns |
|--------|------|--------|---------|
| GET | `/projects` | — | `[{id, workspace, repo_slug, name}]` |
| POST | `/projects` | JSON body | Create/update project |
| PUT | `/projects/:id` | JSON body | Update project |
| DELETE | `/projects/:id` | — | Delete project |
| GET | `/projects/:id/pipelines` | `?page=1&filter=...` | `{pipelines, page, size, total}` |
| GET | `/projects/:id/pipelines/:uuid` | — | `{pipeline, steps}` |
| GET | `/projects/:id/pipelines/:uuid/steps` | — | `{steps}` |
| GET | `/projects/:id/pipelines/:uuid/steps/:stepUuid/log` | — | `{log: string}` |
| GET | `/projects/:id/variables` | — | `{variables}` |
| GET | `/projects/:id/pipelines/:uuid/log-variables` | — | `{variables}` (parsed from log) |
| POST | `/projects/:id/pipelines/:uuid/stop` | — | Stop pipeline |
| POST | `/projects/:id/trigger` | `{target, branch, variables}` | Trigger new pipeline |
| POST | `/projects/:id/repositories` | — | Refresh repository list |

### State Management (Webapp)

All state is in `webapp/src/stores/appState.js` using Svelte writable stores:

- `projects` — Array of project configs
- `activeProjectId` — Index into projects array
- `activeProject` — Derived store from activeProjectId
- `currentScreen` — `'list' | 'detail' | 'logs' | 'trigger' | 'manage'`
- `pipelines`, `pagination` — Pipeline list data
- `selectedPipeline`, `selectedSteps`, `selectedVariables`, `selectedLogVariables` — Detail view data
- `logContent`, `logStepName`, `logPipeUUID`, `logStepUUID` — Log viewer state
- `detailState`, `listState` — Loading states
- `notification` — Toast message {type, message}
- `searchQuery`, `filterBranch` — List filters
- `showError(msg)`, `showSuccess(msg)` — Convenience functions

### UUID Cleaning

Bitbucket returns step UUIDs wrapped in `{...}` braces, e.g. `{abc123-def456}`. The function `cleanUuid()` strips these braces. This is **critical** for step log lookups — the raw UUID won't match BB API expectations. Applied in both `server/server.go` (for webapp) and `ui/list.go` (for TUI).

## Known Patterns & Gotchas

### 1. Svelte 5 Runes
- Uses `$state()` for component-local reactive state (NOT `let`)
- Uses `$effect()` for side effects (NOT `onMount`)
- Uses `$derived()` for computed values
- Store access still uses `$storeName` syntax
- Template conditionals: `{#if}`, `{:else if}`, `{:else}`, `{/if}` (not `{#else}`)

### 2. API fetch patterns
- All API calls in `api.js` return parsed JSON
- Auth uses Basic auth per project (read from config)
- `headerOverrides()` handles form-encoded POST bodies with proper Content-Type
- IMPORTANT: `{...headerOverrides(), ...headers}` must come BEFORE `{...headers, ...headerOverrides()}` to avoid stripping auth

### 3. Pipeline states (Bitbucket API)
- `IN_PROGRESS`, `PENDING`, `COMPLETED`, `FAILED`, `ERROR`, `STOPPED`, `NOT_STARTED`
- State object: `{name, stage, result: {name}}`
- Step states use the same values

### 4. Build output
- Vite builds to `../server/webapp-dist/` (configured in `vite.config.js`)
- The Go server embeds this directory via `embed` (not currently — uses `http.FileServer`)
- The SPA fallback in `server.go` serves `index.html` for all non-API routes

### 5. Config file
- Path: `~/.config/bbc-pipeline-tui/config.yml`
- Format: `projects: [{name, workspace, repo_slug, username, app_password}]`
- Projects are identified by their array index (`project_id`)
- The config wizard (TUI) and ManageProjects (webapp) both write to this file

### 6. Caching
- `bitbucket/cached_client.go` wraps the API client with a JSON file cache
- Cache is stored at `~/.cache/bbc-pipeline-tui/repositories.json`
- Only repository listing is cached; pipeline data is always fetched live

### 7. CSS / Styling
- Pure CSS (no Tailwind, no component library)
- Dark theme: bg #0f1419, cards #16181c, borders #2f3336, text #e7e9ea, muted #71767b
- Status colors: success #3fb950, error #f85149, running #d29922, stopped #8b949e
- Buttons use rounded-full (9999px border-radius)
- Monospace font stack: 'SF Mono', 'Fira Code', 'Cascadia Code', 'Consolas'

## Common Tasks

### Adding a new API endpoint
1. Add handler in `server/server.go`
2. Add fetch function in `webapp/src/stores/api.js`
3. Add any needed stores in `appState.js`
4. Build frontend: `cd webapp && npx vite build`

### Adding a new screen/page
1. Create component in `webapp/src/lib/`
2. Add screen name to `currentScreen` usage in `App.svelte`
3. Add route in `App.svelte` template
4. Add any stores needed in `appState.js`

### Testing the webapp
```bash
go run . -serve          # Start backend on :8080
cd webapp && npm run dev # Dev server with HMR on :5173 (proxies API to :8080)
```
